The one rule

The export-control risk of AI is not "using an AI to help design a rocket." It's the specific data you type into the prompt. So before you send anything to an AI, ask one question: what's in this prompt? The answer routes you to one of three tiers. When in doubt, drop to the more restrictive tier.

Our local model stack (Ollama, on Exos machines, zero data leaves the building) is always a safe choice for any task. If you're unsure, use it.

Step 1 — Classify the prompt before you send it

If the prompt contains any of the following, it's Tier 1 (Local only):

  • Export-controlled technical data — our specific engine or vehicle designs, dimensions, RDRE/injector/chamber details, performance numbers, GNC internals, test data, drawings, or manufacturing know-how (this is USML Category IV / ITAR).
  • CUI, NDA-covered material, or anything marked proprietary/controlled.
  • Exos business development, strategy, capital/financials, cap table, customers, or competitive information.
  • Personnel / HR / personal data.

If none of that applies and the content is general, public, or non-controlled → Tier 2 (Grok-ZDR) is allowed.

Tier 1 — LOCAL ONLY (the vault)

Use only the Exos local model stack (Ollama on our machines — zero data egress). No external AI service, ever, for this content.

Covers: controlled technical data (engine/vehicle design specifics, performance, test data, drawings, GNC), CUI, NDA material, BD/strategy/capital/competitive material, customer identities, and HR/personal data.

If a Tier 1 task is too hard for the local model, escalate (Step below) — do not move the data to an external tool just to get a better answer.

Tier 2 — GROK-ZDR (external, non-controlled only)

Allowed uses only: general engineering physics and detonation theory from public literature; math and sanity-checks; synthesis of public information; drafting/formatting non-sensitive text; coding on non-controlled, non-proprietary code.

Conditions — all required:

  • Use the enterprise xAI/SpaceXAI API with Zero Data Retention (ZDR) turned ON (the response carries an x-zero-data-retention header). ZDR means your inputs aren't stored or trained on.
  • Never the consumer Grok app or the Grok Build CLI. A July 2026 audit caught the consumer Grok Build agent uploading entire code repositories and history — including files it was told to ignore. API + ZDR only.
  • No repo/file-tree uploads. Paste only the specific non-controlled snippet you need.
  • If a topic borders controlled technology, run it through export screening first.
Remember: Grok is a SpaceX-owned product now (xAI was acquired by SpaceX in Feb 2026). Even under ZDR, keep all competitive/BD/strategy content out — that's a Tier 1 item.

Tier 3 — NEVER

  • Never send ITAR/EAR-controlled technical data, CUI, or NDA material to any external AI — with or without ZDR.
  • Never route federal or CUI data through Grok — it is not FedRAMP-authorized; there's no compliant government/CUI path today.
  • Never use consumer Grok / Grok Build CLI on Exos machines or repositories.
  • Never feed Exos BD, strategy, capital, or competitive information to xAI/SpaceXAI.

Any exception requires written approval from the CEO and the Empowered Official — no self-authorization.

When you're unsure

Hold the prompt in Tier 1 (Local) and request an export/classification determination through the Empowered Official before using any external tool. Don't guess upward.
